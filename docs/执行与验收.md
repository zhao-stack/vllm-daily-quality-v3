# 执行与验收

## 环境

Windows PowerShell 为本包测试平台。Git、可用的 GitHub connector 或已登录的 gh、目标机 Spreadsheets 插件及 bundled Python/Node/node_modules。Python 校验脚本仅使用标准库；schema_check.py 严格实现固定 schema 已使用的关键字，遇到新关键字或格式会阻断，不能当通用 JSON Schema 引擎。由 agent 调用依赖加载工具获得路径，不硬编码原机用户名，不复制 token、.git 凭证、代理或整个插件缓存。不同账号可以使用。

本包不代建插件，也不要求安装同账号。若目标 agent 无 artifact-tool，应先补齐兼容运行环境，不静默换成另一个 Excel 写库并声称版式一致。完整 main2main analyzer 仅门控通过才需要；选干净的 vllm-ascend 引擎 checkout 并记录 engine SHA，按配套 skill 调用。

## 离线复现命令

以下变量由目标机依赖加载工具提供；RunDir 是全新目录。所有命令从交接包根执行。

```powershell
& $Python scripts/handover.py verify
& $Python scripts/handover.py prepare-sample --run-dir $RunDir --node-modules $NodeModules
& $Python scripts/handover.py pipeline --run-dir $RunDir
& $Node "$RunDir/build_report.mjs" --records-only
& $Python scripts/handover.py audit --run-dir $RunDir --records-only
& $Node "$RunDir/build_report.mjs" --template-preview
# 此时 agent 查看模板预览；按 Spreadsheets skill 要求首次 authoring 前调用其操作标记工具。
& $Node "$RunDir/build_report.mjs"
& $Node "$RunDir/build_report.mjs" --recalc-probe
& $Python scripts/handover.py audit --run-dir $RunDir --compare-example
```

输出原 main-lys 日志及 pipeline-execution-receipt.json；日期键只是流水线文件名，实际窗口以 ISO 时间为准。deep_analyze.py 零输入返回 1：脚本如实保留该返回码，并生成标明 empty_input 的适配器空结果，不冒称原程序成功处理记录。

查看 RunDir/renders 的 11 页渲染，逐页检查表头/首中尾、长文本、数字和截断。必要时按范围补渲染。保存 visual-review.json，列出 sheet、checked_ranges、结论、时间、检查者和报告 hash。不能仅“生成 PNG”就宣布视觉通过。脚本不自动签署视觉验收，也不自动更新水位。

## 正式运行

先执行 SKILL.md 的证据采集和 AI 分析，按字段合同准备独立新目录。将 runtime/build_report.mjs 和 templates/main-lys-v3-11-sheets.xlsx 复制到该目录为 build_report.mjs/template.xlsx，并用加载工具目录建立 node_modules junction。不要复制样例 PR 到正式运行。按上面 pipeline→records→audit→build→probe→audit 顺序执行；正式运行不加 compare-example。

包内 pipeline 默认使用已验收 vendor 快照。若远端 main-lys 有更新，由 agent 获取干净固定 SHA 的工作流目录，完整阅读变更、校验文件 git blob，使用 `pipeline --workflow-dir <目录>`；report_config.mainLys/blob 同步记录实际版本。先在离线样例上验收 schema/生成器兼容性，出现新枚举时明确处理，不能任意映射或绕开校验。

完整正式验收还包括：精确时间边界、GraphQL totalCount/cursor/分片并集、去重、merge parent/diff、评论分页、pins/verified、分类矩阵和责任人、跨表原因、全部 PR 覆盖、外部源码版本、11 页实际视觉检查。audit 结构通过不代表这些语义/采集 gate 自动通过。

## 切换与水位

本包快照水位为 2026-09-23T01:01:54.707+08:00；不包含未完成的后续运行。交接当天以原任务**届时最新成功水位**为准，不能过几天仍直接用旧快照。

1. 双方约定正式执行者，确认原机没有正在写入的正式任务。
2. 用户明确停用旧任务后，导出最后成功 state、对应报告 hash；核对原报告可用。
3. 目标机恢复水位，报告路径映射到实际存在的归档文件；保留 source 信息，不直接用旧机 C 盘路径。
4. 试跑从该 cutoff 到新触发 cutoff；不滚动终点。
5. 验收全部通过，记录报告绝对路径/SHA256、SHAs、三类/五类计数、runStartedAt、cutoff 和历史。
6. 更新前比较 state 原字节 hash，若变化立刻停止，不覆盖其他运行。使用同目录临时文件+原子替换，持有独占运行锁；失败水位不动。
7. 创建每天 01:00 香港时间任务时使用 docs/每日执行提示词.md。此包不包含自动迁移调度器，避免双机重复执行。
