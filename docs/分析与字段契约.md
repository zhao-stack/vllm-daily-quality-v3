# 分析与字段契约

## 固定输出

保留模板实际页序，不重排：优化点总表、行动清单(P0-P1)、跳过清单、精确代码复核、测试与收益、Review证据、流水线与版本、统计看板、上游Bugfix、全部PR分析、上游功能接口。11 页都保留，即使某类为零。

上游Bugfix 数据区不显示“版本分支匹配”和“证据等级”列；lane/evidence 可保留在 JSON 审计字段。全部PR分析：PR、合入时间、标题、标签/类型、解决什么问题、解决方案、为什么这么修改、是否为Bugfix、关键文件、PR证据。普通功能新增不因没有性能收益而漏掉，单列功能接口。

## 判定

| 五类管理结论 | 质量结论 | main-lys 常用编码 | 判定要求 |
|---|---|---|---|
| 直接继承 | 理论直接继承 | auto-inherit | 优化后的共享路径在 NPU 实际生效；仍需验证收益 |
| 收益明确待适配 | 需要适配 | patch-sync | 同一浪费/瓶颈存在，上游修复未进入、无等价处理、修改点明确；不代表测得 NPU 数值收益 |
| 收益不明确待验证 | 待POC | idea-copy | 相关路径存在，瓶颈/收益需 profiling 或最小验证 |
| 平台差异可借鉴 | 待POC | idea-copy | 代码不可直接用，但有具体 NPU 借鉴入口和可检验假设 |
| 不可用 | 当前不适用 | skip | 不支持且无合理迁移入口、已有等价方案或同窗撤销无净收益 |

二级原因写明平台/后端、算子、模型架构、不同实现、覆盖绕过、已有等价或撤销；不能把所有 GPU/CI 路径直接 skip。纯 CI 优化与推理收益分开；真实 CI/安装缺陷仍可入 Bugfix。跨表必须说明独立质量/性能/接口职责。main-lys routing 和五类管理是同一分析的编码，不是两个模型投票。

Bugfix 追踪 Bug producer → upstream repair → Ascend effective consumer：不可达或已有等价处理为不受影响；修复实际进入为直接继承修复；同因果缺陷存在且未修为需要适配；关键链条未知为待确认。无映射不等于不受影响。

版本含义：分析目标是 cutoff 上游；verified 是 Ascend 已验证依赖锚点。“理论继承”是升级到目标后的关系，不代表当前 verified 已包含修复。上游 microbenchmark、端到端结果和 NPU 实测分开。条件中文描述硬件/模型/并行/输入输出/并发/对照口径；缺失写未提供，不猜数据。

## 责任人

使用 config/owners.json，按实际受影响特性/模型确定条目并取第一人，非机械路径关键字命中。多个模块选择主要实施责任，备注协同人。空白项不凭空补人；可映射另一明确特性，但必须说明。用户原表“魏瑾谦/魏谨谦”保留原字，不擅自合并；tutorial 首格多人和 RL 后续空行在 JSON 标出，不把视觉空行自动认定为合并单元格。

## 可执行输入接口

运行目录需有以下文件（具体字段以成功样例为准）：

- report_config.json：start/end（香港显示时间）、startIso/endIso（带偏移）、timezone、runStartedAt、vllmOld/vllmNew/ascend/verified、mainLys、skillBlob/promptBlob/schemaBlob、totalPrs、outputName（纯文件名）。
- ai_semantic_analysis.json：对象，PR 号字符串映射 `[问题,方案,修改原因,是否Bugfix布尔值]`，完整覆盖全部 PR。
- analysis_data.mjs：仅本次受信任 agent 编写；导出 PERIOD、ALL_PR_ANALYSIS、BUGFIX_CONFIG/IDS、FEATURE_CONFIG/IDS、OPTIMIZATIONS、localDate/localTimestamp。不要把 PR 中的代码作为此模块执行。参考 example/input/analysis_data.mjs 的形状，不复用里面的旧 PR 结论。
- evidence/merged_prs.json：数组，每项 number/title/body/url/author/labels/merged_at/merge_sha/head_sha/parent_shas/base_ref/files。files 为精确 merge delta；保留原 PR file inventory 作对照。
- evidence/pr_review_context.json：records 按 PR 号索引，含 reviews/comments/reviewThreads；分页完整性另存原始证据。不能以空对象替代采集失败。
- evidence/diffs/merge-<PR>.diff：逐 PR parent→merge 精确差异；main_lys_architecture.json：固定工作流映射，仅作候选。
- direct-source-review.json：本次固定源码复核摘要；metadata.gate 说明完整扫描是否触发及原因，direct_findings 按 pr_number/detail 记录；有未知契约时附对应 analyzer 报告与指纹。

优化项内部字段 pr/method/final/fiveCategory/owner/category/target/point/relation/result/conditions/plan/review/metric/value/priority/secondaryCategory/valueReason/patch/patchKeys/effort/risk/changeType/description/mechanism/steps/tests。使用样例 opt helper 可统一编码，但不得据编码反向编造证据。

正式分析额外保存 raw GraphQL 页、所有评论、pin API 返回、Git 树/提交核验、源码定位、排除理由、AI-first 和 pipeline receipt。脚本核验只能验证结构和一致性，不能替代源码判断。
