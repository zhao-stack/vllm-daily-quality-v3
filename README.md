# vLLM 每日质量报告交接包（main-lys V3）

交接日期：2026-09-29。用于另一位同事、另一台机器或另一个 agent；不要求使用原账号，不包含登录凭证。

## 先看结论

本包固定了 11 页模板、报告生成器、责任人映射、分析规则及成功样例。**它是 agent 执行包，不是“运行 Python 就能自动完成源码语义分析”的无人值守程序。** Agent 负责采集证据、逐项分析并填写结构化输入；脚本负责运行原 main-lys 分类程序、生成和校验 Excel。

已成功样例：2026-09-22 01:00:58.960 至 2026-09-23 01:01:54.707（香港时间，左闭右开），52 个 PR，28 条 Bugfix、18 条优化、16 条功能接口（可跨表，不相加）。原始 Excel、输入、Review、diff、分页和历史验收结果均在 `example/`。

## 对方怎么开始

1. 解压到任意可写目录，不要改包内文件。打开一个以该目录为工作区的新 agent 会话。
2. 把 `docs/接收方启动提示词.md` 全文发给 agent。先做离线复现，不立即启动正式定时任务。
3. 使用自己的 GitHub 授权。启用 Spreadsheets 插件及其 bundled runtime。安装 Git；CLI 采集时还需要 GitHub CLI。代理按目标机配置，不沿用原机端口。
4. 可直接按文件路径读取本包 skill；如需安装到 Codex，运行 `scripts/install.ps1 -SkillsRoot <目标机skills目录>`。安装不会覆盖同名 skill，遇到同名先停下来比较版本。
5. 通过样例复现后，按 `docs/执行与验收.md` 做正式首跑；经双方确认后再接续水位并配置每天 01:00 的任务。

## 一致性与限制

- 复现模式使用固定证据和分析输入，验收表结构、PR 集合、分类数量、字段内容与公式；不要求 XLSX 压缩包逐字节相同。
- 新分析遵循相同规则，但不同模型重新分析可能得出不同判断，须保留证据与差异解释，不能保证逐字一致。
- main-lys 固定版本为 `2c815be15c4e094447c38d67f666e590492f4c28`，这是成功样例的已核验版本，不冒称始终是远端最新。正式运行实时检查远端；如有更新，先比对 prompt/schema/程序、记录新 SHA，再执行结构回归，不能静默改版式。
- Spreadsheets 插件/运行时不复制、不 npm 私自替代；目标机通过其依赖加载工具提供 Node/Python/包目录。字体不同可能产生排版差异，目标机仍须视觉验收。
- 完整 main2main 扫描是条件依赖：只有门控通过才需要带 `tools/vllm_interface_contracts` 的干净、固定 SHA 引擎 checkout。未打包原机带未提交修改的引擎，避免把本机试验代码当正式依赖。
- 本次交接不重跑每日 PR 分析，不修改原成功水位，不关闭原定时任务、不代建接收方定时任务。

详细测试结果见 `docs/本机验收结果.md`。交接时请把整个 ZIP 发给对方，不要仅发 SKILL.md。
